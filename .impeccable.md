# .impeccable.md — FIREPath

> Design source of truth for FIREPath, a free FIRE (Financial Independence / Retire Early) calculator PWA that compares five FIRE types on one interactive timeline. This file reflects the design system already in the codebase (DESIGN.md, globals.css, fire-colors.ts, calculator components). It is descriptive of what exists, not aspirational.

## Users

Three personas drive every design decision (PRD §2-2):

- **FIRE pursuers (25–45)** — already saving toward independence; want to compare *when* each FIRE type is reachable on a single timeline. Numerically literate, return repeatedly, expect precise tabular data.
- **FIRE explorers (22–35)** — curious newcomers; want a low-friction "is this even possible for me?" answer. Need approachable defaults and forgiving inputs, but still respect data density.
- **Finance bloggers / creators** — embed and link the tool; care about shareable results (URL-hash share, dynamic OG images) and a credible, screenshot-worthy chart.

Primary optimization target: the FIRE pursuer's comparison workflow (9 sliders → 5 result cards → 1 chart). The explorer is served by good defaults on that same surface, not a separate "lite" experience.

## Aesthetic

**Industrial / Utilitarian fintech — "a Bloomberg terminal met a modern fintech app. The numbers do the talking."** (DESIGN.md)

- **Data-first:** Content hierarchy is values first, chrome second. Large `tabular-nums` figures (e.g. result cards use `text-3xl font-bold tabular-nums`), restrained decoration.
- **Confident & precise:** Tight, intentional spacing; grid-disciplined layout (320px sticky sidebar + flexible chart area, max-width 1440px); no decorative flourishes that don't carry information.
- **Decoration level: intentional, not zero.** Subtle surface treatments only — `shadow-sm` default rising to `shadow-md` on hover, gradient area fill under the chart line (20% → 0%), a 4px left border on FIRE cards in the type color. Decoration always encodes meaning (color = FIRE type, border = identity).
- **Trust signals:** Deep teal brand, neutral surfaces, monospace for raw values in inputs and tooltips, honest empty/edge states ("80+" when a goal isn't reached by 80).

Anti-goals: playful illustration, gradient-maximalism, glassmorphism, oversized rounded "consumer app" softness, anything that obscures a number.

## Palette

Colors are authored as **OKLCH** in `globals.css` for the neutral/semantic system, with **literal hex** for the locked brand and FIRE-type tokens. Both light and `.dark` themes are defined; dark mode follows system preference via the `.dark` class variant.

### Brand (locked, hex)
| Token | Hex | Use |
|-------|-----|-----|
| `--brand-primary` | `#065F53` | Primary actions, chart area stroke, PWA theme color, trust anchor |
| `--brand-light` | `#0D9488` | Hover states, gradients |
| brand-dark | `#042F2E` | Heading emphasis (from DESIGN.md; not yet a CSS var) |

`--primary` in OKLCH (`oklch(0.436 0.077 180.1)` light / `oklch(0.704 0.123 182.5)` dark) is the teal-derived shadcn primary used by buttons, focus, etc.

These encode meaning across chart lines, card borders, and reference lines. They are chosen to be mutually distinguishable on the chart and AA-legible. Do not recolor, reorder, or theme them.

## Typography

- **Single family: Inter** (`next/font/google`, bound to `--font-sans`, applied on `<html>`). This is a **deliberate, load-bearing choice — not generic AI defaulting.** Inter is selected for its excellent `tabular-nums` support, which is essential for aligning currency and percentage columns in the result cards and tables. Treat "use Inter" here as an informed financial-data decision; do not "upgrade" it to a trendier display face.
- **Monospace:** `--font-mono` → `--font-geist-mono`. ⚠️ Geist Mono is referenced in `globals.css` but **not currently loaded** in `layout.tsx` (only Inter is imported), so `font-mono` resolves to the **system monospace stack** today. `font-mono` is applied to raw editable values (slider number inputs, `class="font-mono"`) and chart tooltip values. ## Motion

**Minimal-functional.** Motion clarifies state change; it never entertains. Durations live in the 150–300ms band.

- **Default transition:** 200ms ease-in-out.
- **Hover:** 150ms.
- **Chart recalculation:** 300ms (Recharts `animationDuration={300}`).
- **Mobile sheet (param panel) open/close:** 300ms.
- **Card highlight:** `scale(1.02)` over 200ms plus shadow lift (`shadow-sm → shadow-md`) on hover/focus, used to cross-link a result card with its chart reference line (`isHighlighted`).
- No parallax, no entrance choreography, no looping/ambient animation. Respect reduced-motion expectations (keep transitions short and optional).

## Spatial

- **Base unit:** 4px. Density: **comfortable** (not cramped, not airy).
- **Scale:** 1=4 · 2=8 · 3=12 · 4=16 · 5=20 · 6=24 · 8=32 · 10=40 · 12=48 · 16=64.
- **Radius base:** `--radius: 0.625rem` (10px). Derived ramp in `@theme`: sm=×0.6, md=×0.8, lg=×1.0, xl=×1.4, 2xl=×1.8 … Cards use `rounded-xl`; buttons `rounded-md`.
- **Layout:** Grid-disciplined. Max width **1440px (7xl)** centered with `px-4`. Desktop (lg+): **320px sticky sidebar** (parameters) + flexible content/chart area. Mobile (<md): parameters move to a **bottom sheet**, content goes full-width.
- **Breakpoints (min-width, mobile-first):** sm 640 · md 768 · lg 1024 · xl 1280.
- **Cards:** padding 16–24px; FIRE result cards carry a **4px left border** in the type color (`borderLeftWidth: 4px`) as identity.
- **Chart container:** `rounded-xl` border, card background, p-4/p-6; dashed muted grid (`strokeDasharray="3 3"`); reference lines dashed `5 5` (Coast `8 4`).

## A11y

Target: **WCAG 2.1 AA.**

- **Contrast:** 4.5:1 minimum for text. FIRE-type colors chosen for distinguishability + AA legibility; verify any colored text-on-surface usage.
- **Focus ring:** 2px, `ring-ring/50` (global `outline-ring/50` on `*`; cards use `focus-visible:ring-2 focus-visible:ring-ring`). Never remove focus visibility.
- **Keyboard:** full tab navigation through every interactive element. Result cards are `role="button"` + `tabIndex={0}` and mirror hover behavior on focus/blur so keyboard users get the same chart cross-highlight as mouse users.
- **Labels:** every slider has an `aria-label` with its parameter name; number inputs have `aria-label="{label} value"`; result cards expose a descriptive `aria-label` summarizing reach age and target.
- **Chart:** must remain interpretable to screen readers (descriptive text); color is never the *only* signal — pair with labels/values.
- **Color independence:** Coast is additionally distinguished by a dash pattern (`8 4`), not just hue, since it shares amber with Warning.
- **Performance budget (UX a11y-adjacent, PRD):** LCP < 2.5s, FID < 100ms, CLS < 0.1.

## Principles

1. **The numbers do the talking.** Lead with data; chrome recedes. Every figure that can be aligned gets `tabular-nums`.
2. **FIRE-type color is sacred semantics.** The five hues mean specific things across chart, cards, and reference lines. Never recolor, retheme, or reuse them for non-FIRE meaning.
3. **Intentional decoration only.** Shadows, borders, and gradients must encode information (state, identity, magnitude). If it's purely ornamental, cut it.
4. **Grid discipline.** 4px spacing system, fixed sidebar + fluid content, one max-width. Layout is predictable and dense in the comfortable range.
5. **Motion is feedback, not flair.** 150–300ms, functional, reduced-motion-respectful.
6. **Trust through honesty.** Client-side math, transparent formulas, truthful edge states ("80+"), no dark patterns, no fake urgency. A11y AA is part of trust.
7. **Inter + tabular-nums is a decision, not a default.** Don't "modernize" the typeface; it was chosen for financial alignment.
8. **One surface, all five types.** The comparison-on-a-single-timeline is the core value prop; resist designs that split or hide types behind tabs.
